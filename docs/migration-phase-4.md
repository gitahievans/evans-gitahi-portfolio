# Phase 4: project routes and assets

Completed on `codex/nextjs-migration`, 2026-10-16. Scope: three case studies, shared presentation, project navigation, assets, metadata, and static legacy URLs. Phase 5 verification/cleanup remains next. No deployment occurred.

## Implementation

- `src/app/projects/[slug]/page.tsx` enumerates Scorelearn, LadyShelf, and SceneIt with `generateStaticParams`, sets `dynamicParams = false`, and calls `notFound()` for missing content. Known projects are rendered at `/projects/{slug}/`; unknown paths have no exported file. The host must serve missing files with HTTP 404 rather than an SPA fallback.
- `src/content/case-studies.ts` holds typed narrative data extracted from active source HTML. The shared Server Component `components/projects/case-study.tsx` renders the hero, definition lists, engineering brief, ordered architecture flow, decisions and tradeoffs, practice panels, readiness table, demonstrated skills, competencies, and project navigation. All factual copy and external destinations remain intact, including explicit product limitations.
- Styling uses literal Tailwind utilities and existing semantic palette/primitives. Three centralized layout tokens cover the hero proportions, section columns, and readiness-table minimum width. Hero columns split above 1100px; section columns and practice/fact grids split above 800px; metadata and architecture flow adapt at the source's small breakpoint. Cards remain still, content remains visible, and reduced-motion rules apply globally.
- Each page has one h1, labeled sections with h2 headings, and h3 article titles. Readiness uses native table, caption, column headers, and row headers, replacing incomplete ARIA table markup. The table can scroll within a labeled keyboard-focusable region on narrow screens. Status is communicated by preserved wording using existing contrast-tested semantic text colors.
- Shared header/footer accept a project-page mode. Their section links target `/#section`, the logo targets `/#profile`, and Projects is current in both header menus. Homepage viewport tracking does not subscribe on project pages. Existing disclosure enhancement/theme behavior is reused.
- Homepage and related-project actions use canonical directory URLs. `scripts/export-legacy-projects.ts`, run by `npm run build`, copies each generated project HTML file to `/projects/{slug}.html`. These are full compatible pages with root-relative links/assets, accessible without JavaScript; no hosting-specific redirects or automatic navigation are required. No absolute canonical domain was invented while hosting remains unspecified. Legacy entries are supplied in production output, not the Next development server.
- Three screenshots are migrated to descriptive public WebP names with 640/960/1600px width variants. A native picture source supplies responsive selection; Next Image supplies explicit intrinsic dimensions, alt text and eager/high-priority hero loading. No image API is needed by the static host. The nine variants total approximately 484 KiB (the original three PNGs totaled approximately 7.5 MiB). Aspect ratios are preserved; screenshots are no longer cropped. The existing portrait favicon is copied to `/images/evans-gitahi.jpg` and declared in root metadata. Resume URL is unchanged. Original assets remain as legacy reference until phase 5.
- Each project has its original descriptive metadata and a title using the root title template. Project content stays on the server; only shared navigation/theme controls are client boundaries.
- Production builds now use Next's supported Webpack option. Turbopack failed in this execution environment while attempting a local build-worker port bind, including the elevated attempt; Webpack completed the same static production export. No dependencies changed.
